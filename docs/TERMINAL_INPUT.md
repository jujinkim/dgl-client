# 터미널 마우스·조합 키 입력

크기만 바뀌는 화면 동기화에서는 같은 연결·세션·pane의 키·텍스트 입력을 기존 제한된 큐로 받습니다.
스냅샷을 읽는 동안 IME 조합과 커서 키·붙여넣기 모드를 유지하고, 실제 전송 직전 대상 세대를 다시 검사합니다.
좌표에 의존하는 마우스·pane 조작은 크기가 확정될 때까지 제한합니다. 실제 연결 검사·복구·대상 변경 중
거절된 입력은 자동 재전송하지 않으며 안내는 3초간 복구 주기당 한 번 표시합니다.

## 하단 단축키와 조합키

설정 메인의 **터미널·입력 → 하단 단축키**에서 사용 중인 키의 표시 순서를 편집합니다.
드래그 중에는 순서 미리보기와 삽입 위치를 표시하고 가장자리에서 스크롤하며, 유효한 드롭에서만 저장합니다.
취소·Esc는 순서를 보존합니다. 위/아래 버튼은 키보드·접근성 대안이며 제외한 키를 다시 추가하면 끝에 붙습니다.
상세 화면을 닫으면 설정 메인의 스크롤과 진입 행 포커스를 복원합니다.

바이트를 보내는 `TerminalKey`는 매크로·볼륨키 계약으로 유지하고, `TerminalShortcut`은 일반 키 또는 Ctrl·Shift·Alt 토글을 나타냅니다.
`terminalShortcuts`의 기존 문자열 이름·순서·빈 목록을 유지합니다. 누락된 설정과 기본값 복원에서만 Ctrl·Shift·Alt를 기존 기본 목록 앞에 넣습니다.
제외 목록은 전체 항목과 사용 중 목록의 차이이며 별도로 저장하지 않습니다.

토글은 현재 입력 대상의 메모리에만 둡니다. 같은 버튼으로 해제하고 실제 키보드 modifier와 합집합으로 결합합니다.
다음 하단 일반 키나 실제·화면 키보드의 확정 입력을 인코딩해 한 번 제출할 때 해제합니다. 실패 입력은 재전송하지 않습니다.
탭·그룹·pane·연결 세대 변경, 모달, 백그라운드 진입은 해제하며 화면 크기·IME 높이 변경과 하단 버튼 포커스 이동에는 유지합니다.
붙여넣기·텍스트 작성·CLI·볼륨 매크로·마우스·터미널 프로토콜 응답은 조합하거나 소비하지 않습니다.
macOS의 원격 Ctrl을 Command로 치환하지 않으며 로컬 OS 편집 단축키는 유지합니다.

Rust `input::encode_key`를 GPUI와 UniFFI에서 함께 사용합니다. 키 이름·확정 텍스트·modifier·application cursor mode를 받으며,
기존 Ctrl 키나 Shift+방향키에도 토글을 합칩니다. Ctrl+비 ASCII/다문자, Shift+비 ASCII 확정처럼 legacy 프로토콜로 표현할 수 없는 조합은 전송하지 않고 안내하며 토글을 유지합니다.
Android는 xterm의 공개 `attachCustomKeyEventHandler`·`onKey`와 입력/조합 이벤트로 출처를 구분합니다.
xterm이 중복을 제거한 IME 확정 델타만 인코딩하며 이미 생성된 임의 `onData` 바이트를 다시 변환하지 않습니다.
조합을 시작한 pane·연결 세대를 지연된 확정 입력까지 보존하고 제출 시 검사합니다.
Android의 조합 글자와 입력 textarea는 실제 표시된 커서 좌표에 맞춥니다.
스냅샷을 복원하는 동안에는 기존 위치를 유지하고 최종 렌더와 함께 갱신합니다.
화면 캐시에는 입력 보조 요소를 복제하지 않습니다. 조합 확정·중복 방지는 계속 xterm이 담당합니다.

## 텍스트 작성

데스크톱 하단 입력 도구는 오른쪽 터미널 영역 안에만 표시합니다. 화면을 분할해도 하나를 유지하며 활성 그룹의 선택 탭에 적용합니다. `텍스트 작성`은 왼쪽, CLI 메뉴는 오른쪽에 고정하고 가운데 단축키만 가로로 스크롤합니다. Android는 키보드·텍스트 작성 버튼을 왼쪽에 고정합니다. 양쪽 하단 버튼은 밝은·어두운 테마와 hover·포커스 상태에서 배경색과 테두리색을 맞춥니다.

데스크톱은 중앙 팝업의 여러 줄 편집기를 사용합니다. Enter는 줄바꿈, 방향키·Home/End는 커서 이동, Shift+방향키는 선택이며 시스템 편집 단축키로 선택·복사·잘라내기·붙여넣기를 처리합니다. 자동 줄바꿈과 세로 스크롤을 지원합니다. 열면 편집기에 포커스를 주고 배경 터미널 입력을 차단하며 취소·Esc·전송 성공 후 이전 포커스를 복원합니다.

하단 키보드 버튼은 실제 IME 표시 상태에 따라 열기·닫기를 전환합니다. 열 때 기존 WebView와 xterm 입력창에 포커스를 돌려주며 SSH 연결이나 터미널을 다시 만들지 않습니다. 좁은 창에서는 터미널 → 열린 연결 탭 → 단축키 → 화면 키보드 순서로 배치합니다. 탭은 36dp, 단축키는 기본 두 줄 70dp이며 설정에서 한 줄 36dp로 전환합니다. 버튼은 30dp, 위아래 여백은 3dp, 좌우 여백과 버튼·줄 간격은 4dp입니다. 두 줄은 저장 순서대로 위→아래→다음 열에 놓고 같은 열의 너비를 맞춥니다. 왼쪽 열은 키보드 위·텍스트 작성 아래, 오른쪽 열은 CLI 메뉴를 아래에 고정하며 가운데만 함께 가로 스크롤합니다. 빈 목록도 두 줄 높이를 유지하고 CLI 메뉴는 오른쪽 열 위로 엽니다.

`텍스트 작성`은 네이티브 여러 줄 편집 다이얼로그를 엽니다. 한글 조합·선택·복사·붙여넣기를 사용할 수 있고 입력창의 Enter는 줄바꿈입니다. 전송은 `전송` 버튼으로만 시작합니다. `Enter 함께 보내기`는 기본 꺼짐이며 켜면 텍스트 전송 성공 후 별도의 Enter 키 입력을 한 번 보냅니다. Enter는 붙여넣기 데이터에 합치지 않으며 고정 조합키를 적용하거나 소비하지 않습니다. 줄바꿈은 xterm의 붙여넣기 규칙을 따르므로 bracketed paste를 지원하지 않는 원격 셸에서는 각 줄이 실행될 수 있습니다.

초안과 선택 위치는 **연결 인스턴스별 메모리**에 유지합니다. 닫기·탭 전환·회전 후 복원하며 설정 파일·저장 상태 Bundle·클라우드 파일에 쓰지 않습니다. 전송 성공, 연결 제거, 앱 프로세스 종료 시 비웁니다. 연결 종료만 하고 탭을 유지하면 초안도 유지됩니다. 원격 터미널에 이미 입력된 내용을 가져오지는 않습니다.

전송 시 xterm의 현재 bracketed paste 모드와 줄바꿈 처리를 사용합니다. 입력 큐에는 붙여넣기 제어 문자를 포함하여 64 KiB 이하인 텍스트 요청을 제출하고 완료 결과를 기다립니다. Enter 옵션을 켰다면 텍스트 요청 성공 후 대상을 다시 확인하고 Enter를 별도 요청으로 전송합니다. 빈 입력·크기 초과·대상 변경은 전송하지 않습니다. 두 단계가 끝날 때까지 편집과 중복 전송을 막고, 모두 성공해야 초안을 비웁니다. 실패하면 초안과 오류를 남기며 자동 재전송하지 않습니다. Enter 단계만 실패하면 텍스트는 이미 전송되었다고 안내합니다. 수동 재전송은 텍스트도 다시 보내므로 원격 상태를 먼저 확인하세요. 성공은 전송 큐의 완료를 뜻하며 원격 명령의 실행 성공을 뜻하지 않습니다.

다이얼로그를 연 연결·세션·패널 세대와 각 요청 제출 직전 대상을 확인합니다. IME·회전·창 크기 변경의 크기 세대는 대상 비교에서 제외합니다. 대상이 바뀌면 초안을 확인하고 다이얼로그를 다시 열어 새 대상을 선택합니다. 다이얼로그 동안 배경 터미널 입력과 Android 볼륨 단축키를 차단합니다. 데스크톱도 현재 pane의 bracketed paste 모드와 기존 붙여넣기의 줄바꿈 규칙을 적용하며 텍스트와 Enter 각각의 완료 결과를 기다립니다.

좁은 창은 현재 연결의 `…` 메뉴에서 `패널 도구 접기`·`패널 도구 펼치기`, 대화면은 입력 도구 위 아이콘으로 패널 도구 행을 접거나 펼칩니다. `mobilePaneToolbarVisible`은 모든 모바일 탭에 공통 적용되어 로컬 설정에 저장됩니다. 기존 설정에 이 필드가 없으면 `true`로 시작합니다. Kotlin/Rust는 같은 설정 fixture를 읽으며 Windows 빌드·패키징 경로는 유지합니다.

Android 840dp 이상에서는 입력 도구를 오른쪽 작업 공간 아래 하나만 두고 버튼 높이를 48dp로 표시합니다.
키보드·볼륨키·단축키·CLI·텍스트 작성은 활성 그룹의 선택 탭으로만 보냅니다. 터미널 터치·포커스는 해당 그룹을 먼저 활성화합니다.
모달 표시 중에는 다른 그룹도 입력을 받지 않습니다. 키보드가 열려도 논리 크기로 분할 가능 여부를 판단하고,
남은 영역에 기존 트리·비율로 모든 그룹을 표시합니다. 각 터미널의 논리 크기와 WebView는 유지합니다.
실제 창이 작아져 최소 공간을 확보할 수 없을 때만 활성 그룹을 임시 확대합니다.

## 동작

데스크톱(Mac·Windows 공통 Rust 코드)은 다음 입력을 처리한다.

| 입력 | 동작 |
| --- | --- |
| 휠·트랙패드 | 이동량만큼 원격 휠 이벤트를 보내며, 작은 픽셀 이동은 누적한다. 0 이동은 보내지 않는다. 마우스 모드가 꺼져 있으면 로컬 기록을 스크롤한다. |
| 가로 휠 | 원격 마우스 모드에서 좌우 휠 이벤트를 보낸다. |
| 실제 Ctrl+세로 휠 | 위로 확대·아래로 축소하며 연결별 임시 글자 크기 10–28을 적용한다. 원격 휠 이벤트와 로컬 기록 스크롤을 보내지 않는다. 우측 상단 `↺`는 최신 기본값으로 초기화하며 포커스를 유지한다. |
| 클릭·드래그·호버 | 왼쪽·가운데·오른쪽 버튼을 지원한다. 원격 앱이 요청한 1000(클릭), 1002(버튼 드래그), 1003(호버 포함) 모드를 구분한다. 같은 셀의 반복 이동은 보내지 않는다. |
| 마우스 인코딩 | 기본 X11, UTF-8(1005), SGR(1006)을 지원한다. 기본 X11 좌표 범위를 넘는 이벤트는 보내지 않는다. |
| Shift+마우스 | 원격 마우스 모드에서도 로컬 텍스트 선택·기록 스크롤을 사용한다. 원격으로 누른 버튼은 영역 밖이나 Shift를 누른 상태에서도 해제한다. |
| Ctrl/Alt+마우스 | 클릭·드래그·호버·휠에 modifier 정보를 포함한다. 실제 Ctrl+세로 휠은 글자 크기 조절에 사용한다. |
| Shift/Ctrl/Alt+방향키·Home/End·Insert/Delete·PageUp/PageDown·F1–F12 | 조합 정보를 xterm 시퀀스에 포함한다. 여러 modifier를 동시에 누를 수 있다. |
| Ctrl+문자·Alt+문자 | Ctrl+A–Z, Ctrl+Space 및 제어 문자 별칭을 처리한다. Ctrl+Alt 조합은 ESC와 제어 바이트를 함께 보낸다. |
| Shift+Tab·Alt+Enter·Alt+Backspace | 각각 역방향 Tab, ESC+Enter, ESC+Backspace를 보낸다. |
| 일반 문자·IME | GPUI 입력기 경로에서 입력을 받는다. Shift로 만드는 대문자·기호는 이 경로를 사용한다. |

호버는 원격 앱이 1003 모드를 켠 경우에 전달된다. 단순 셸 프롬프트에서 포인터를 움직이는 것만으로 입력을 보내지 않는다. 대체 화면에서 마우스 모드는 꺼져 있고 1007 모드가 켜져 있으면 세로 휠을 위·아래 방향키로 보낸다.

macOS의 Command 앱 단축키와 Windows에서 실제로 지정한 Ctrl+Shift 앱 단축키는 앱 조작에 사용한다. Windows에서 지정하지 않은 Ctrl+Shift+방향키 등의 조합은 터미널로 전달한다.

Android는 xterm.js에서 키/IME 확정 입력의 출처와 커서 모드를 받고 공통 Rust 인코더를 사용한다. 나머지 `onData`는 UTF-8 텍스트로, `onBinary`는 문자당 원래 1바이트로 전달하여 기본 마우스 보고의 128–255 바이트를 보존한다.

Android 터미널은 스크롤바 공간을 예약하지 않고 원격 행·열을 그대로 표시한다. 컨테이너 전체 너비로 가용 열 수를 측정해 기존 원격 크기 조절 경로에 전달하며, 원격 화면이 더 넓으면 가로 드래그로 이동한다. 글자 한 칸보다 작은 잔여 픽셀은 여백으로 남는다.

키보드 표시·숨김·높이 변경은 원격 터미널 resize나 화면 복원을 요청하지 않습니다. 시스템 바·화면 잘림을 제외한
논리 크기로 행·열을 계산하고, 회전·멀티윈도우·실제 창 크기·폰트 변경만 반영합니다. 상단 메뉴와 하단 탭·단축키는
키보드 위에 유지하며 터미널 표면만 잘라서 표시합니다. Kotlin은 논리/가시 크기를 CSS 픽셀로 정규화해 IME 상태·
렌더러 세대와 함께 전달하고, 오래된 갱신이나 분리된 표면의 크기 요청은 버립니다.

키보드가 열리면 원래 터미널의 하단을 보이게 패널을 올립니다. 가려진 부분이 있을 때 우측의 3 CSS px 스크롤바를
계속 표시하며, 투명한 24 CSS px 조작 영역은 터미널 열 수를 줄이지 않습니다. 본문 세로 드래그는 8 CSS px 방향 판정 후
손가락과 1:1로 패널을 이동하고, thumb 드래그는 전체 범위에 비례합니다. 상단·하단에서 멈추며 관성은 없습니다.
이 제스처는 원격 휠·방향키·마우스 입력이나 합성 클릭을 보내지 않습니다. 키보드를 닫으면 이동량을 초기화하고
다시 열면 하단에서 시작합니다. xterm 출력 이력의 읽기 위치는 패널 이동과 별도로 보존합니다.

키보드가 닫혔을 때는 기존 스크롤 동작을 사용합니다. 세로 터치 이동이 8 CSS px 이상이고 가로 이동보다 크면 스크롤을 시작한다. 손가락을 아래로 움직이면 이전 내용(휠 업), 위로 움직이면 다음 내용(휠 다운)이며, 한 행 높이마다 한 단계씩 누적하고 손을 떼면 멈춘다. 휠을 지원하는 TUI는 xterm의 기존 마우스 보고, 일반 셸은 로컬 출력 이력, 마우스를 지원하지 않는 대체 화면 TUI는 위·아래 방향키를 사용한다.

비활성 pane의 첫 드래그는 선택만 수행하고 다음 드래그부터 스크롤한다. 드래그는 키보드를 열지 않으며 탭·가로 이동·pane 경계 조절·핀치와 구분한다. 대상 변경·재접속·입력 차단·핀치·포인터 취소 시 남은 이동량을 버리고, 합성 클릭이나 키보드·IME 경로로 중복 전송하지 않는다.

이번 범위는 전통적인 xterm 입력이다. 데스크톱의 Kitty 키보드 프로토콜, modifyOtherKeys, 키 해제 이벤트, 픽셀 단위 마우스 보고(1016), 링크 호버 UI까지 지원한다는 의미는 아니다. OS가 먼저 사용하는 단축키와 실제 키보드 배열·IME 동작은 기기별 확인이 필요하다.

프로토콜 기준: [xterm 제어 시퀀스](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html), [xterm.js onBinary](https://xtermjs.org/docs/api/terminal/classes/terminal/#onbinary).

# Google Drive·iCloud Drive 파일 동기화

dgl은 사용자가 선택한 `dgl-sync.json`을 읽고 쓴다. Google Drive API, OAuth,
CloudKit, 자체 서버·계정은 사용하지 않는다. 로그인·클라우드 업로드·다운로드는
설치된 Drive 앱 또는 Android 문서 제공자가 처리한다.

## 플랫폼

| 플랫폼 | Google Drive | iCloud Drive |
|---|---|---|
| macOS | Drive 데스크톱 앱의 동기화 폴더 | Finder의 iCloud Drive 폴더 |
| Windows | Drive 데스크톱 앱의 동기화 폴더 | iCloud for Windows의 동기화 폴더 |
| Android | 시스템 파일 선택기의 Google Drive 문서 | 지원하지 않음: 기본 iCloud 문서 제공자가 없음 |

Android Google Drive 앱이 시스템 선택기에 읽기·쓰기 가능한 문서를 제공해야 한다.
문서 제공자·계정 정책에 따라 쓰기·오프라인 접근·업로드 시점이 다를 수 있다.
데스크톱에서 선택한 폴더가 실제로 동기화되는지는 Drive 앱에서 확인한다.
dgl이 임의 경로를 검색하거나 계정·사용자 폴더를 추측하지 않는다.

## 연결

1. 첫 PC에서 Drive 앱에 로그인하고 동기화할 전용 폴더를 만든다.
2. dgl **설정 → 설정·호스트 동기화**에서 **Google Drive 폴더 선택…** 또는
   **iCloud Drive 폴더 선택…**을 누른다. 폴더에 `dgl-sync.json`이 없을 때만 생성한다.
3. 다른 PC에서는 같은 클라우드 폴더가 내려온 뒤 그 폴더를 선택한다.
4. Android에서는 **Google Drive 파일 연결**로 같은 파일을 선택한다.
   Android에서 시작하려면 **새 파일**을 누르고 저장 위치로 Google Drive를 선택한다.
   기존 파일이 있는 경우 새 파일을 만들지 않는다. Android는 중복 이름을 별도 문서로 만든다.
5. 가져온 호스트에 처음 연결하면 이 기기의 비밀번호 또는 개인키를 등록한다.
   호스트키 신뢰도 각 기기에서 따로 확인한다.

첫 연결 시 공유 파일에 있는 공통 설정을 적용하고 기기의 기존 호스트를 병합한다.
기기마다 한 저장소만 연결한다. Google Drive와 iCloud Drive 사이를 자동으로 복제하지 않는다.
다른 폴더·문서로 바꿀 때 이전 저장소의 변경 이력을 새 저장소에 옮기지 않는다.

PC는 앱 실행 중 15초 간격으로, Android는 앱 복귀 시 및 전경에서 15초 간격으로 확인한다.
**지금 파일 동기화**로 수동 실행할 수도 있다. 호스트 편집 중에는 적용을 보류한다.
파일 I/O는 백그라운드에서 수행한다. Android 영속 URI 권한으로 재실행 뒤에도 같은 문서를 연다.
연결 해제는 공유 파일·가져온 호스트·기기의 자격 증명을 삭제하지 않는다.

**파일 반영 완료는 클라우드 전송 완료가 아니다.** Drive 앱의 전송 상태를 확인한 뒤
다른 기기에서 파일을 동기화한다. PC 스트리밍 파일은 필요하면 Drive 앱에서
오프라인 사용/다운로드 유지를 지정한다. Android 백그라운드 상시 실행은 하지 않는다.

## 데이터 범위

| 동기화 | 기기에서만 유지 |
|---|---|
| 호스트 ID·별칭·주소·포트·사용자명·인증 방식·즐겨찾기 | 비밀번호·개인키·키 암호·자격 증명 참조 |
| 테마·글자 크기·스크롤백 | 최근 연결·세션·패널·터미널 출력 |
| 질문·응답·오류에 대한 앱 내 알림 설정 | OS 알림 설정·권한, 볼륨 키·매크로, 화면 분할 배치 |
|  | 신뢰한 SSH 호스트키·지문 |

Rust 공통 코어가 허용된 필드만 직렬화한다. 기존 `settings.json`을 그대로 복사하지 않는다.
주소·사용자명은 공유 파일에 평문으로 들어간다. 별도 앱 계층 암호화는 제공하지 않으며
선택한 Drive 계정·폴더의 접근 제어를 따른다. 호스트의 주소·포트·사용자명·인증 방식이
다른 기기에서 바뀌면 기존 자격 증명을 새 대상으로 재사용하지 않고 다시 등록하도록 한다.

## 충돌·오류 처리

- 변경마다 기기 식별자·논리 순서·이전 변경을 기록하고, 받은 변경과 합집합을 만든다.
  기기 시각이나 파일 수정 시간만으로 승자를 정하지 않는다.
- 서로 다른 호스트·설정 항목의 변경은 병합한다. 같은 호스트를 동시에 수정하거나
  수정과 삭제가 겹치면 두 값을 보존하고 설정 화면에서 유지할 값을 선택한다.
  호스트 하나는 한 항목으로 취급한다. 충돌 중에는 해당 기기의 현재 값을 유지한다.
- 삭제 기록도 보관한다. 과거 파일을 읽었다는 이유만으로 삭제된 호스트를 부활시키지 않는다.
- 공유 파일 쓰기 전에 로컬 변경 이력을 원자적으로 저장한다. 쓰기 실패·앱 재시작
  뒤에도 그 이력으로 다시 병합한다. 로컬 설정을 읽지 못한 PC는 동기화를 중지한다.
- 공유 파일은 같은 파일/문서 ID를 유지하며 내용을 갱신한다. 교체 저장으로 Android의
  영속 URI를 무효화하지 않는다. 읽기 직후 다른 변경이 보이면 재시도한다.
- 잘못된 JSON·다른 데이터셋·미지원 버전·16 MiB 초과·변경 20,000개 초과는 적용/쓰기를
  중단한다. 자동 실행은 사라진 파일을 새로 만들지 않는다.

일반 파일 제공자는 여러 기기의 원자적 비교·교체를 제공하지 않는다. 업로드가 겹쳐
파일이 오래된 내용으로 보이더라도 각 기기의 보존 이력이 다음 교환에서 다시 합쳐진다.
이를 위해 해당 변경을 가진 기기가 다시 실행되어야 한다. Drive가 별도로 만든 충돌 사본을
자동 탐색하거나 모든 기기의 이력 삭제 이후까지 복구를 보장하지 않는다.
중간 쓰기 실패로 공유 파일 자체가 손상되면 원본을 덮어쓰지 않고 중단한다.
Drive 이전 버전/백업에서 유효한 같은 데이터셋 파일을 복원한 뒤 다시 동기화한다.

로컬 연결·이력은 설정 디렉터리의 `cloud-sync.json`에 저장한다. Android에서는
`noBackupFilesDir/rust-candidate-v1`에 둔다. 이 파일도 비밀번호·개인키·토큰을 담지 않지만
기기별 경로/문서 URI를 포함하므로 공유 파일로 사용하지 않는다.

## 검증 범위

Rust 코어는 민감정보/매크로 제외, 로컬 인증·신뢰 유지, 다른 기기 변경 병합,
지연된 과거 파일, 수정·삭제 충돌과 사용자 선택, 로컬 적용 실패 재시도,
다른 호스트 대상에 대한 인증 재사용 차단, 파일 형식·버전·인과 관계 검증을 검사한다.
PC 파일 어댑터는 임시 디렉터리에서 읽기·쓰기·손상/누락 파일 보존을 검사한다.
Android 검사는 테스트 APK 전용 ContentProvider로 영속 권한·실제 ContentResolver I/O·
두 기기 병합·충돌·쓰기 실패·어댑터 재시작·연결 해제를 다룬다.

실제 Google Drive·iCloud 계정에서의 업로드 완료·다른 물리 기기로의 전달,
Windows 네이티브 실행, 실제 파일 선택기 UX는 별도 인수 대상이다.
구체적인 실행 결과는 [검증 기록](VALIDATION.md)을 따른다.

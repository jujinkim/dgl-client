# Migration contract v1

`contract-v1.json` is UTF-8 JSON shared by the legacy JVM tests and future Rust tests.
It contains synthetic data only. Bytes are lowercase hexadecimal; text is Unicode.
Expected values are fixed data, never generated by the implementation under test.

- `protocol`: feed the UTF-8 `wire` at every possible byte boundary and one byte at a
  time; compare every event in order, then call `finish`. `error` means rejection
  during feed or finish. A failed feed must poison the parser.
- `escapes`: capture escaping differs from live octal escaping.
- `commands`: `op` and arguments select a typed constructor. Check both control
  `wire` and `shellWire`; do not feed a shell string to a shell in this test.
- `keys`/`input`: stable serialized key names, UTF-8 bytes, explicit Enter, newline
  conversion, empty input and the inclusive 65,536-byte limit. `repeat` is compact
  fixture notation only; it is not a settings field.
- `settings`: decode `source` as settings with unknown keys ignored, encode with
  defaults included and compare JSON trees with `expected`. A repository round trip
  must preserve the same model. Error cases must leave original bytes untouched.
- `state`: tmux q-escaped field boundaries and typed remote IDs.

These fixtures freeze observed compatibility, not every behavior of the old app.
Snapshot/live ordering, cancellation, backpressure, actual SSH and GUI/IME require
the separate acceptance matrix in `docs/migration/FEATURE_MATRIX.md`.

Run: `./gradlew :app:desktopTest` then the exact test inventory verifier. Changing a
fixture requires explaining the compatibility change and advancing the contract
version for incompatible changes. Never update expectations merely to pass a port.
